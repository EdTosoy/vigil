# Vigil deployment boundaries

Read root instructions, Phase 15 documentation and ADR-018 before changes.

The separate repeat-cycle executor is locally implemented under ADR-021; read `docs/phase15/sydney-cycles.md`. This task authorizes local implementation and verification only. Its cloud flag grants no authority. Future locked plans, exact saved-plan applies, one-shot tasks, sandbox destination creation/retirement and teardown need separate explicit authorization. Preserve historical first-use guards, old claims and state versions. Current-HEAD ECS sources use application auth with narrow SSM references and owner-free verification; never substitute historical images or public snapshot mode. Backend State-role permissions remain unchanged.

`infra/startup` is a separate, locally prepared single-host proposal; read [its runbook](../docs/phase15/startup.md) and ADR-020. The user authorized local completion/verification only. `pnpm aws:startup:validate:offline` may copy allowlisted sources into a new private temporary directory, initialize with `-backend=false` and run validation/mocked plan-only tests without AWS credentials. Never run Terraform in the startup source directory, initialize its remote backend, publish images or provision/change cloud resources under this local authorization. Existing demo/bootstrap gates below remain unchanged.

- Historical Phase 15 evidence used `iamadmin-general`, account `163596511125`, region `us-east-1`; its state/resources are foreign to the Sydney preparation. Never use them as fallback or migrate/copy their state.
- Sydney D1A/D1B permit only offline preparation and read-only STS preflight with explicit `edtosoy`, account `747240980964`, `ap-southeast-2`, exact STS assumed role `AccountFullAccessRole` (rotating session suffixes allowed). Reject inherited credential/profile/region/endpoint/Terraform overrides. Recheck actual STS identity immediately before every future mutation; a cached receipt is never authorization.
- Sydney artifacts belong only under `.deployment/747240980964/ap-southeast-2/{bootstrap,demo}/`, including isolated work roots, `TF_DATA_DIR`, seed state, backends, plans, environment/secrets, logs and history. Reject traversal/symlinks and foreign/missing backend or plan metadata; never read legacy private files to populate the new namespace.
- All mutating deployment/observer workflows remain disabled after D1B, pending D2 readiness, concrete reviewed plans and explicit approval. Tracked Terraform sources now describe Sydney; ignored backends/state/caches in the source roots remain foreign. Never invoke Terraform directly there. `pnpm aws:validate:offline [bootstrap|demo]` copies only allowlisted sources/lockfiles/tests into fresh private work/data directories and permits only backend-disabled init, validation and mocked plan-only tests. Remote init, migration, unlocking, image publication, resource creation/destruction and DNS changes remain unauthorized.
- D2B adds only `AWS_PROFILE=edtosoy AWS_REGION=ap-southeast-2 pnpm aws:bootstrap:plan` (no arguments): guarded live reads and an exact create-only S3/ECR proposal in a fresh implicit-local seed workspace. Require absent seed state/backend metadata and fresh full gross-budget evidence; provider 6.68.0 omits some budget data fields. Plan receipts are evidence, never provisioning authorization. Do not reuse a failed seed, initialize remote state, or enable mutating wrappers to obtain a plan.
- The explicit D2C authorization adds a single-use `aws:bootstrap:execute` exception for the exact reviewed twelve S3/ECR creates. It regenerates and compares the saved plan/configuration against the checksum-pinned D2B baseline, rechecks STS, and retains local state with no retry/migration/destroy. An execution marker blocks reuse, including partial failures. All other mutating wrappers remain disabled. The operator confirmed percentage budget units and explicitly accepted the inactive recipient; never claim alert delivery or silently repair the budget.
- D3A authorizes only `aws:images:publish` for committed-source `linux/amd64` admin/ops/stripe builds into the three existing `flow-demo/{admin,ops,stripe}` repositories. Require all local smokes before any push, immutable unique revision tags, fresh exact STS, repository/tag checks, manifest/config digest proof and unchanged bootstrap state. Its private publication claim blocks automatic reruns/partial retries. Never log ECR tokens or retain Docker auth; do not enable general deployment or alter repository policies. Runtime must use verified digest URIs.
- D3C `aws:runtime:inputs` is local-only: target-scoped 0700 directories/0600 files, hidden terminal entry, no secret arguments or legacy input fallback. Configuration UUID syntax is not configured-identity proof; Stripe's sandbox book and the dashboard's synthetic book are distinct. Never mark bindings/DNS/backend writes authorized from editable local metadata. Its saved scope is review-only; the separate D3E exception below uses explicit lock-only approval, never editable metadata, state payload writes or bootstrap migration.
- D3E adds only the no-argument `aws:runtime:plan` exception for the initial stopped-service proposal and existing explicit lock-only approval. Reuse one unclaimed source/input preparation; pin Terraform 1.15.3, exact backend and immutable images. The backend must assume the verified `arn:aws:iam::747240980964:role/vigil/VigilSydneyRuntimePlanRole` with a `vigil-d3e-*` session and fixed restrictive policy denying state/all other writes and nonconditional lock puts. Provider reads retain the separate browser-login `edtosoy` identity. Verify exact live planner trust/policy and backend STS identity; retain only sanitized observations, never raw SDK logs. If that session or any extra permission is unavailable, stop; never fall back to unrestricted backend credentials. Retain the execution claim even on failure; no automatic retry/unlock or apply/destroy/migration capability is added. Local D3C scope JSON still grants no authority.
- The D3E restrictive backend session policy is embedded in any resulting saved plan. Never apply such a proposal: future provisioning needs separately authorized state-write capability and a freshly generated/compared plan before review, rather than discovering a state-write denial after creating resources.
- D3F is preparation only and authorizes zero AWS mutations. `aws:runtime:release inspect` is read-only. The separate state-role policies under `infra/runtime-state-role/` and three missing service-linked roles require explicit IAM approval; never modify the planning/browser roles. Future `plan <exact-package-id>` requires those prerequisites and a fresh FREE/ACTIVE account check, uses only the proposed state-role backend, and compares complete resources/configuration/source hashes to the pinned D3E baseline. Future `apply --reviewed <fresh-run:sha256>` requires a review no older than 15 minutes, unchanged secure inputs/executor/backend, absent current/historical state and lock, fresh caller/Free Plan checks and an exclusive retained attempt claim. Do not execute it without separate approval of that concrete plan and exact state writes. Partial/unknown outcomes retain state and never retry automatically. Teardown requires its own deletion-only saved plan/review ID, unchanged observed state version and separate execution approval; credit exhaustion alone must not block approved cleanup. No foundation state bucket, ECR repository or backend IAM role is part of runtime teardown. General legacy deployment gates remain unchanged.
- IAM role paths must come from authoritative IAM evidence, never reconstruction from the path-free STS assumed-role ARN. The browser role is `role/managed/AccountFullAccessRole` and trusts `account-access.amazonaws.com`, not self-assumption. Do not change its trust as a planner workaround. The separate backend-only role and its one inline policy were explicitly approved, created and verified; its local policy files grant no authority for further IAM changes. `aws:runtime:preview` is an explicit non-deployable local projection: omit the S3 backend in a fresh namespace, retain normal local locking, save no executable Terraform plan and never promote its JSON review into remote-plan/apply authority.

- Inspect saved plans and verify identity before every apply. Deployment tooling rejects bootstrap deletes and unexpected resource types.
- State is sensitive, encrypted and versioned; use native S3 locking. Never commit state, saved plans, generated backend configuration or local variable files.
- Sydney uses manual Cloudflare DNS for `vigil.edtosoy.com`, ACM validation CNAME outputs and a later ALB CNAME. No Route 53 zone/record is managed or discovered. STOP for actual ACM CNAME publication and public verification before enabling certificate validation/listeners/services. Keep records DNS-only for initial verification. Never modify `flow.edtosoy.com`; its historical child-NS checkpoint is historical evidence only.
- The existing `mdp-monthly-gross-usd-5` budget is read-only: account-wide monthly USD 5, excluding credits/refunds and including tax. Never import, duplicate, update or destroy this other-owned account guardrail. Verify notification delivery separately before billable work.
- Never migrate the Cloudflare parent zone or require Cloudflare tokens/providers.
- No NAT, public database, workload AdministratorAccess, live Stripe, alternate queue or financial semantic changes.
- Runtime credentials remain narrow. Owner credentials belong only to one-shot migration/provisioning. Never expose secrets through outputs, plans/logs shared with users, task environment literals or images.
- A successful apply is not financial assurance or Phase 15 completion. Record deployed proof and actual runtime destruction separately.
