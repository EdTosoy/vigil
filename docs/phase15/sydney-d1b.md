## Sydney runtime and cost boundary

Network defaults use two distinct Sydney zones, `ap-southeast-2a` and `ap-southeast-2b`, validated against the Sydney set. D2 must confirm these names are available to this account; no account-specific AZ query occurred. Public task/ALB subnets route through an internet gateway. Fargate services assign task public IPv4 addresses; outbound TCP 443 supports image pulls, AWS operational endpoints and Stripe. Task ingress permits only the ALB-to-application rules. PostgreSQL subnets have an isolated route table with no internet default route, and DB ingress is only TCP 5432 from the five explicit task groups. RDS remains nonpublic. No NAT or paid VPC endpoints are introduced. This follows [AWS's documented public-subnet Fargate networking](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/networking-outbound.html).

All Fargate task definitions retain Linux `X86_64`, 256 CPU units, operations/admin 1024 MiB and ingress/worker/verifier 512 MiB. Local builds explicitly use `linux/amd64`. RDS `db.t4g.micro` is an ARM database host; that does not require ARM application images. ARM64 application portability is not claimed or selected. ECS execution trust and repository ARNs now use only the new account and Sydney. Execution roles retain narrow ECR/log/SSM actions; runtime task roles receive no AWS API policies. Logging remains three-day retention in Sydney.

RDS remains PostgreSQL 18.6, `db.t4g.micro`, 20 GiB gp3, encrypted, Single-AZ, no autoscaling/backup retention/final snapshot/deletion protection, no enhanced monitoring or Performance Insights. This is approved only as a future disposable synthetic/sandbox demo design; no persistence/HA claim is made. Catalog support observed at D0 is dated evidence, not creation eligibility or quota proof. An unavailable Free Plan feature blocks deployment; do not upgrade the plan or substitute larger paid infrastructure.
